### 关于「算力是否必须机载」的推论

- 【事实】原文 p2：「机器鱼需**搭载**独立电源、**自主控制系统**及传感器模块」「漏油点检测模块需**集成于机器鱼本体**」「必须完全自主运行，**禁止远程操控**或预编程固定路径」
- 【推论】把感知放到池边的计算机上、只把指令送回鱼体，与上面三条的字面要求相冲突。无人在环的板外推理是否算「远程操控」原文没有界定，但这是**裁判主观判定**范围的事
- 【待验证】所以在组委会书面确认之前，**默认按「全部算力在鱼上」设计**，并把板外算力当作不可用的优化手段。这直接限制了算法复杂度上限（[strategy](strategy.md) 的决策门）
- 【推论】开发机上装了 GPU 与深度学习框架，**不构成「比赛时可用 GPU」的证据**——开发环境 ≠ 部署环境（[hardware](hardware.md)）

> [!IMPORTANT]
> 问题 1 与问题 2 是**关键路径**。在拿到答案之前：
> - 视觉方案要按「判别特征未知」设计成可快速插拔的——判别规则与阈值放在配置里，而不是散落在代码里（[不变量 7](invariants.md)）
> - **不要开始相机 / 镜头选型**，也不要挑中间件——这两个都直接取决于问题 2 与问题 5 的答案

## 运行环境

- 【事实】赛题 PDF 对运行环境**没有任何规定**：没说操作系统、语言、中间件、算力放在哪
- 【设计】**用户已指定：本项目工具链与 [`reference/pipe_inspector_raspberry`](../../reference/pipe_inspector_raspberry-main/) 一致** → 树莓派 + Python + OpenCV + MAVLink `RC_CHANNELS_OVERRIDE` + ONNX Runtime + `RPi.GPIO`。逐项出处见 [reference-pipeline](reference-pipeline.md) 第 1 节
- 【推论】这个选择与 PDF 的「算力必须在鱼上」相容（树莓派就是机载伴飞计算机），也与「禁止远程操控」相容
- 【待验证】平台**具体**接口仍未确认：推进通道数与通道号、飞控型号与串口设备、相机型号与安装。见 [reference-pipeline](reference-pipeline.md) 第 9 节
- 【设计】参考项目是**结构与接口的起点**，不是可以照搬的代码：它的 17 条缺陷必须修掉，清单见 [reference-pipeline](reference-pipeline.md) 第 6 节
- 【设计】选型约束（来自 [architecture](architecture.md)）：
  1. 能落盘原始帧与中间结果，且**不阻塞控制环**
  2. 控制环 ≥20 Hz、灯带提取 ≥30 Hz（但见 [hardware](hardware.md) 的帧率推算——这个门限随速度变化）
  3. 能在**树莓派**上跑起来（不是开发机；树莓派无 CUDA，[hardware](hardware.md) 的 GPU 只用于训练，不用于部署）
- 【设计】目录结构按 [architecture](architecture.md) 的四层划分：`vision` / `estimator` / `fsm`+`reporting` / `control`，外加一个 `platform` 适配层隔离飞控接口

## 标定

### 离线标定（赛前，用实物 + 水池）

1. 相机内参：棋盘格 → 焦距、主点、径向畸变
2. 相机外参：安装高度 `h` 与俯仰 / 偏航安装角（用灯带已知 500mm 内缩反推）
3. 像素尺度 `mm_per_px(h)`：拍 ⌀3cm 标记实物，量像素直径，反推比例；在不同高度重复
4. 灯带宽度像素范围、起终点黑带宽度像素范围
5. 执行器：给正 / 负指令，记录鱼体转向方向与角速率 → 符号表与量程
6. 端到端延迟：从「触发一次闪光」到「图像中出现」+ 从「指令下发」到「姿态变化」分别测

### 调试窗口清单（**这是唯一能标定误识别点的机会**）

- 【事实】第一轮 10 分钟、第二轮 2 分钟；线上赛另有赛前 10 分钟（[competition](competition.md#赛前准备与调试窗口)）

**10 分钟窗口的固定脚本（按顺序，每步都要计时）**：

| 分钟 | 动作 | 产物 |
| --- | --- | --- |
| 0–1 | 上电自检：相机出图、IMU 出数、执行器响应、语音可闻 | 全绿才继续 |
| 1–3 | 拍 **8 个漏油点 + 5 个误识别点实物**各若干张，逐个记录编号 | 判别特征样本集 |
| 3–5 | 跑判别特征提取脚本，看哪一维可分；选规则 + 定阈值 | 判别规则（写入配置） |
| 5–6 | 用留出的样本验证判别规则；**重点看误识别点被判成漏油点的比例** | 验证结果 |
| 6–8 | 像素尺度与阈值复标（本场光照 / 水深） | 标定产物 v{日期} |
| 8–10 | 全链路预演：手动把鱼放在灯带上，确认巡线、上报、播报、声光 | 通过 / 不通过 |

**2 分钟窗口只能做**：复核标定是否仍然有效 + 确认起终点判定。**不允许**在 2 分钟窗口里做特征选择。

## 测试阶梯

```
1. 离线回放   录制的真实水池视频 → 统计灯带 valid 率、误检/漏检、终点误触发
2. 桌面联调   相机对着打印的场地俯视图（等比例打印）→ 调控制律与状态机
3. 水池静态   鱼放在灯带上，只看不跑 → 验证标定与分割
4. 水池动态   整条路径往返跑 → 整定巡线增益、弯角、起终点
5. 全流程演练 含标定、上报、播报、计时，模拟 150 秒限时
```

- 【设计】第 1 步的**误报率**是准入指标，不是检测率。看不到误报率就不许进入第 4 步
- 【设计】每一次阶梯升级都要留日志（[logs](../logs/README.md)），记「参数 + 现象 + 结论」

## 比赛日清单

### 通用

- [ ] 上电自检脚本能一键跑完并给出红 / 绿（相机、IMU、执行器、语音、灯）

- [ ] 所有硬保护计数器可见：脱离计时、触壁计数、已耗时
- [ ] 一键 `ABORT`（停机且不推进），队员举手前先停机
- [ ] 备用电池 / 备用相机 / 备用灯；充电状态确认
- [ ] 计时演练一次，确认「≤30 秒」档可达

### 线下

- [ ] 确认场地实际尺寸与灯带几何，与 [competition](competition.md) 记录比对，有差异立刻记日志

- [ ] 确认「全身进入终点区」的认定方式

### 线上（原文 p4–p5）

- [ ] 3 个机位就位：机位 1 全景（覆盖水池 + 起终点区 + 队员操作区）、机位 2 起点区侧方特写、机位 3 起点区对面侧特写
- [ ] 回看每个机位的录像，**逐点确认声光信号可见**、语音可辨
- [ ] 腾讯会议在线、开摄像头与麦克风、屏幕共享开启

- [ ] 网络备份（断网 >3 分钟本轮无效）
