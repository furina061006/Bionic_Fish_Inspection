### 关于「算力是否必须机载」的推论（对应编号 5）

- 【事实】原文 p2：「机器鱼需**搭载**独立电源、**自主控制系统**及传感器模块」「漏油点检测模块需**集成于机器鱼本体**」「必须完全自主运行，**禁止远程操控**或预编程固定路径」
- 【推论】把感知放到池边的计算机上、只把指令送回鱼体，与上面三条的字面要求相冲突。无人在环的板外推理是否算「远程操控」原文没有界定，但这是**裁判主观判定**范围的事
- 【待验证】所以在组委会书面确认之前，**默认按「全部算力在鱼上」设计**，并把板外算力当作不可用的优化手段。这直接限制了算法复杂度上限（[strategy](strategy.md) 的决策门）
- 【推论】开发机上装了 GPU 与深度学习框架，**不构成「比赛时可用 GPU」的证据**——开发环境 ≠ 部署环境（[hardware](hardware.md)）

## 运行环境

- 【事实】赛题 PDF 对运行环境**没有任何规定**：没说操作系统、语言、中间件、算力放在哪
- 【设计】**用户已指定：本项目工具链与 [`reference/pipe_inspector_raspberry`](../../reference/pipe_inspector_raspberry-main/) 一致** → 树莓派 + Python + OpenCV + MAVLink `RC_CHANNELS_OVERRIDE` + ONNX Runtime + `RPi.GPIO`。逐项出处见 [reference-pipeline](reference-pipeline.md) 第 1 节
- 【推论】这个选择与 PDF 的「算力必须在鱼上」相容（树莓派就是机载伴飞计算机），也与「禁止远程操控」相容
- 【待验证】平台**具体**接口仍未确认：推进通道数与通道号、飞控型号与串口设备、相机型号与安装。见 [reference-pipeline](reference-pipeline.md) 第 9 节
- 【设计】参考项目是**结构与接口的起点**，不是可以照搬的代码：它的 17 条缺陷必须修掉，清单见 [reference-pipeline](reference-pipeline.md) 第 6 节
- 【设计】选型约束（来自 [architecture](architecture.md)）：
  1. 能落盘原始帧与中间结果，且**不阻塞控制环**
  2. 控制环 ≥20 Hz、灯带提取 ≥30 Hz（但见 [hardware](hardware.md) 的帧率推算——这个门限随速度变化）
  3. 能在**树莓派**上跑起来（不是开发机；树莓派无 CUDA，[hardware](hardware.md) 的 GPU 只用于训练，不用于部署）
- 【设计】目录结构按 [architecture](architecture.md) 的四层划分：`vision` / `estimator` / `fsm`+`reporting` / `control`，外加一个 `platform` 适配层隔离飞控接口

## 上真机：启动与部署

**先说清楚：这不是固件。** 没有烧录、没有 bootloader —— 它是一个 Python 包，启动就是启动一个进程。

- 【事实】命令行入口是 `python -m bionic_fish`（[`__main__.py`](../../src/bionic_fish/__main__.py)）；真机上先装一次 `pip install -e ".[hardware,rpi]"`，之后就不需要 `PYTHONPATH=src`
- 【事实】v2 之后只剩两条路，**区别只在两个口上接什么**：

| 模式 | 命令 | 帧源 | 出口 | 会不会动 |
| --- | --- | --- | --- | --- |
| 仿真 | `python -m sim.run_sim` | `FakeCamera`（渲染） | `SimLink`（记录） | 否 |
| 实物 | `python -m bionic_fish` | `Camera` | `MavlinkLink` + 真 GPIO | **是** |

- 【设计】没有「只开相机不发指令」的台架模式了 —— 想不带硬件验证感知，就写一条针对
  `find_white_pipe` 的测试，或者用 `sim/` 换一份参数。这比多一个运行模式更省事
- 【事实】`--config x.yaml` 两条路都吃：平的 YAML，键名就是 `params.py` 的字段名
- 【事实】`python -m bionic_fish` 的顺序：连 MAVLink（等心跳）→ 开相机 → 解锁（校验
  `COMMAND_ACK`）→ 跑 → **无论怎么退出都上锁**（`finally`）
- 【设计】`disarm` 放在 `finally` 里是**安全要求**，不是整洁：终端状态、异常、Ctrl-C 任何一条退出路径如果不解锁，飞控会保持最后一根杆位，鱼会在没人看的时候继续游

**开机自启**：[`deploy/bionic-fish.service`](../../deploy/bionic-fish.service)

```sh
sudo cp deploy/bionic-fish.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl start bionic-fish
journalctl -u bionic-fish -f
```

- 【事实】该单元**故意没有 `[Install]` 段**，也就是**默认不随开机启动**，理由见下面的 IMPORTANT
- 【设计】`Restart=no`：重启会重新解锁并开一趟新的巡检。`Restart=always` 会把「中途崩溃」变成「鱼自己在池子里又出发一次」

> [!IMPORTANT]
> **启动时机尚未决定。** 规则禁止远程操控与人工干预，而鱼在 10 分钟调试窗口内就已经在池子里了。所以「服务启动了」**不能**等于「比赛开始了」，否则鱼会在队伍还在标定的时候就出发。
>
> 三个候选（一个都没定）：① 物理开关，裁判宣布时由队员扳；② 固定延时 + 宣布时上电（`ExecStartPre=/bin/sleep N`）；③ 入水检测。
> 无论选哪个，都必须满足「裁判宣布开始后 30 秒未启动即结束」—— 那条计时**从宣布开始算，不是从上电算**。
>
> 在定下来之前：**手动启动服务**。

- 【待验证】实机这条路**完全没在真机上跑过**。测试里能守住的只有：四条硬终止真的会终止、丢线不复位舵量、解锁失败要报错。真实串口、飞控、GPIO、相机四段全是空白
- 【待验证】**落盘与可视化调试界面尚未实现**：架构 8.1 把它列为硬要求，但 v2 里没有任何代码读配置、没有任何 `imwrite` / `imshow`（v0.1 的 `Config.artefact_dir` 随线性重写删除）。它是出事时唯一的证据，见 [backlog](../../backlog.md)

## 标定

### 离线标定（赛前，用实物 + 水池）

1. 相机内参：棋盘格 → 焦距、主点、径向畸变（**注意：v2 不做畸变校正**，标出来也只是先知道误差有多大）
2. 相机外参：安装高度与俯仰 / 偏航安装角（用灯带已知 500mm 内缩反推）→ `camera_height_m`（量到**管顶**）与「正下方」对应的行 → `report_row`
3. 像素尺度：拍 ⌀3cm 标记实物，量像素直径 → `mm_per_px_override`（**优先于模型推算**）；同时把 `frame_w` / `frame_h` 改成相机真实输出的分辨率
4. 管道直径 → `strip_width_mm`；起终点黑带宽度与厚度 → `tape_width_px_lo/hi`、`tape_thickness_px_max`、`tape_max_grey`
5. 执行器：给正 / 负指令，记录鱼体转向方向与角速率 → 符号表与量程（`pwm_min` / `pwm_max` / `neutral`）
6. 端到端延迟：从「触发一次闪光」到「图像中出现」+ 从「指令下发」到「姿态变化」分别测

### 调试窗口清单（**这是唯一能标定误识别点的机会**）

- 【事实】第一轮 10 分钟、第二轮 2 分钟；线上赛另有赛前 10 分钟（[competition](competition.md#赛前准备与调试窗口)）

**10 分钟窗口的固定脚本（按顺序，每步都要计时）**：

| 分钟 | 动作 | 产物 |
| --- | --- | --- |
| 0–1 | 上电自检：相机出图、IMU 出数、执行器响应、语音可闻 | 全绿才继续 |
| 1–3 | 拍 **8 个漏油点 + 5 个误识别点实物**各若干张，逐个记录编号 | 判别特征样本集 |
| 3–5 | 跑判别特征提取脚本，看哪一维可分；选规则 + 定阈值 | 判别规则（写入配置） |
| 5–6 | 用留出的样本验证判别规则；**重点看误识别点被判成漏油点的比例** | 验证结果 |
| 6–8 | 像素尺度与阈值复标（本场光照 / 水深） | 标定产物 v{日期} |
| 8–10 | 全链路预演：手动把鱼放在灯带上，确认巡线、上报、播报、声光 | 通过 / 不通过 |

**2 分钟窗口只能做**：复核标定是否仍然有效 + 确认起终点判定。**不允许**在 2 分钟窗口里做特征选择。

## 测试阶梯

```
1. 离线回放   录制的真实水池视频 → 统计灯带 valid 率、误检/漏检、终点误触发
2. 桌面联调   相机对着打印的场地俯视图（等比例打印）→ 调控制律与状态机
3. 水池静态   鱼放在灯带上，只看不跑 → 验证标定与分割
4. 水池动态   整条路径往返跑 → 整定巡线增益、弯角、起终点
5. 全流程演练 含标定、上报、播报、计时，模拟 150 秒限时
```

- 【设计】第 1 步的**误报率**是准入指标，不是检测率。看不到误报率就不许进入第 4 步
- 【设计】每一次阶梯升级都要留日志（[logs](../logs/README.md)），记「参数 + 现象 + 结论」
