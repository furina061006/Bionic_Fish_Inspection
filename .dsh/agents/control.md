# 控制算法（巡线、转弯、起终点、丢线恢复）

> 输入从哪来见 [`vision.md`](vision.md)；上游状态与接口见 [`architecture.md`](architecture.md)。
> 终止条件与时间分见 [`competition.md`](competition.md)。

**本文件状态：`【设计】`**——尚无代码、无水池实测。控制参数全部待整定。

## 被控对象

- 【待验证】自由度与通道数未确认；按最坏情况设计：**只有 `steer`（转向）与 `thrust`（推力 / 摆频）两个标量**（[hardware](hardware.md)）
- 【推论】欠驱动带来的三个后果，决定了整个控制结构：
  1. **无侧向推进**——横向位置只能通过「先转头、再前进」间接改变，因此不能直接对 `e_y` 做高增益控制
  2. **大滞后**——尾摆产生转向力矩与推力都有明显延迟（死时间 + 一阶惯性），纯比例控制必然振荡
  3. **浅水窄池**——横向活动余量小（上 / 下灯带间距约 1000mm，两侧距池壁 500mm），撞壁 3 次即结束，因此**幅值优先于精度**
- 【待验证】上面 2 与 3 的量化前提（滞后时间常数、实际可用横向余量、弯角几何）都还没实测，参数整定不能先于这些测量

## 控制结构：串级 + 前视

```
                 e_y (前视点横向偏差)
   ┌────────────────────────────────────────┐
   │ 外环：位置 → 期望航向                   │
   │   psi_d = atan2(-k_y · e_y , L)         │
   └───────────────┬────────────────────────┘
                   ▼  psi_d
   ┌────────────────────────────────────────┐
   │ 内环：航向 → 转向指令                   │
   │   e_psi = psi_d - psi                    │
   │   steer = Kp·e_psi + Kd·ė_psi + Ki·∫    │
   └───────────────┬────────────────────────┘
                   ▼  steer
   ┌────────────────────────────────────────┐
   │ 限幅 + 抗积分饱和 + 死区                 │
   └───────────────┬────────────────────────┘
                   ▼
                执行器
```

- 【设计】结构化简为「**前视点横向偏差 → 航向 → 转向**」，等价于 Pure Pursuit：前视点由 [vision](vision.md) 在图像上方 70%–85% 高度处给出，**前视距离 `L` 的上限由相机视场决定**（约 0.2–0.4m），不是自由参数
- 【设计】内环需要 `psi`（航向）。**若平台无 IMU**：用灯带切线角 `e_theta` 代替 `psi` 做内环，此时外环输出改为「期望的 `e_theta`」。两种接法的参数不通用，必须记清用的是哪种
- 【设计】积分项很危险：执行器饱和 + 大滞后下积分会windup，导致过弯后长时间过冲。**首选不用积分**；若稳态偏置不可接受，只在 `|e_psi|` 小于阈值时累加，并在饱和时暂停累加
- 【设计】死区用于抑制尾摆自激（小幅来回摆造成推进效率低、纹波大），但死区过大会产生稳态横向漂移 → 撞壁。**死区宽度必须由「池宽 − 鱼宽」反推上限**

## 速度策略

- 【设计】速度不由「想跑多快」决定，而由**三段风险**决定：

| 区段 | 速度目标 | 理由 |
| --- | --- | --- |
| `ALIGN` / 起步 | 最低（先确认灯带在视野中央） | 30 秒未启动即结束；但起步方向错会直接压到分界线 |
| 直道 `FOLLOW` | 高 | 时间分梯度陡（≤10s 得 20 分，[strategy](strategy.md)） |
| 弯角 `CORNER` | 显著降低 | 90° 弯角是大滞后 + 饱和的极端工况，快了必然冲出灯带 |
| 终点接近 `FINISH_APPR` | 低 | 要精确停在终点区内，还要满足「全身进入」 |

- 【设计】速度切换要有斜坡（ramp），不能阶跃：推力阶跃在欠驱动对象上会激发俯仰 / 侧倾，进而破坏相机视线
- 【待验证】直道目标速度与「漏检率」必须联合标定——跑得越快，同一处标记在视野中的帧数越少，时序确认（[reporting](reporting.md)）可能来不及完成

## 90° 弯角

- 【设计】判据：`LineObs.curvature` 超阈值，或中心线出现拐折 / 双候选带（[vision](vision.md) 失败模式表）
- 【设计】动作序列：**减速 → 保持较大转向偏置直到新方向被稳定捕获 → 恢复直道速度**
- 【设计】弯角期间**不要**用前视点横向偏差做外环——弯角处中心线拟合会短暂失真，此时应保持「按上一段确定的方向」开环转向
- 【待验证】弯角半径未知（图上未标）。若弯角近似直角折线而非圆弧，鱼体 600mm 长时的最小转弯半径可能超过灯带宽度 → 必须实测该弯角能否以当前转向能力通过

**闭环转弯必须同时具备三件事**（缺一不可，每一件都有对应的坏结果）：

| # | 要求 | 缺了会怎样 |
| --- | --- | --- |
| 1 | **反馈**：转够角度即停 | 参考项目用「打舵 2 秒」把「转 90°」偷换成「转 2 秒」。转角 = 角速度 × 时间，而角速度随电池、水流、负载变化，且误差**跨弯累积**（[reference-pipeline](reference-pipeline.md) 第 6 节） |
| 2 | **超时**：转不到也停 | 反馈可能失效（无航向源、灯带不可见）。没有超时就是「一直转到撞墙」 |
| 3 | **持续重发**：20–50 Hz，决策没变也照发 | `RC_CHANNELS_OVERRIDE` 会超时（[architecture](architecture.md#一工具链已定) 第一节）。参考项目在两个 `sleep` 之间**静默 3 秒** |

- 【设计】第 3 条最容易漏，因为它不属于控制算法，属于**通信层要求**：弯角期间 `fsm` 可以「不改变决策」，但 `platform` 必须继续按固定节拍发
- 【设计】弯角期间被接管的那一路之外，其余通道**不能因为「转弯策略接管了」就停发**——要么继续按上一拍保持，要么继续跑自己的环

## 起点与终点

**起点（`ALIGN`）**

- 【设计】目标：在起点区内把航向对齐灯带，直到 `LineObs.valid` 且 `|e_theta|` 小于阈值
- 【设计】**必须有超时**：裁判宣布开始后 30 秒未启动即结束比赛（[termination 表](competition.md#比赛过程与终止条件)）。因此 `ALIGN` 的超时必须显著小于 30 秒，超时后**按当前估计直接起步**，而不是继续等待
- 【设计】起点区只有约 500mm，对齐动作的幅度要小，禁止原地大角度旋转（可能压到黑色分界线被计为偏离）

**终点（`FINISH_APPR`）**

- 【设计】收到 `CrossObs` 后不停机，继续沿当前航向前进 `body_length + margin` 再停，以满足「**全身进入**终点区」的判定
- 【待验证】`body_length` 需实测；`margin` 需按制动距离 + 水流漂移估计
- 【设计】终点线的接受**必须带状态机上下文**：起点附近也会看到同样的黑带，必须排除（[不变量 6](invariants.md)）
- 【设计】到达终点后停机但保持控制电——不要掉电，也不要继续推进

## 丢线恢复（`LINE_LOST`）

这是**最危险**的状态：它同时受三条硬约束夹击（脱离 >10s 终止、撞壁 3 次结束、150s 超时）。设计原则是**「宁可慢、不可乱」**。

| 级别 | 触发 | 动作 | 风险控制 |
| --- | --- | --- | --- |
| L1 短暂 | 丢线 < 0.3s | 保持上一帧转向，推力降到中档 | 多数丢线由灯带上的黑贴片遮挡引起，能自然恢复 |
| L2 中等 | 0.3–2s | 减速到低档，按最后已知航向直行 + 小幅左右扫掠 | 扫掠幅度受「池宽 − 鱼宽」限制 |
| L3 长时 | 2–10s | 减速最低，沿最后已知航向低速推进并加大扫掠；优先向「上次看到灯带的一侧」回搜 | 计时逼近但未到终止线 |
| ABORT | ≥10s 或 触壁计数 ≥3 | 停机（`ABORT`） | 硬终止条件，不可协商 |

- 【设计】回搜方向优先选「上次看到灯带的那一侧」而不是固定方向：分界线和池壁的位置关系已知，错误方向会直接撞壁
- 【设计】必须**同时**维护「脱离计时」和「触壁计数」两个保护计数器，并在可视化界面上显示（现场需要肉眼确认还剩多少余量）
- 【待验证】平台是否提供碰撞 / 触壁信号。若不提供，只能用「横向偏差饱和 + 姿态突变」间接推断，可靠性不足 → 应向平台方确认

## 参数整定

| 参数 | 含义 | 获取方式 |
| --- | --- | --- |
| `L` | 前视距离 | 由相机视场上限与直道稳定性折中；先取视场上限的一半 |
| `k_y` | 外环增益（横向偏差 → 期望航向） | 仿真粗调 + 水池细调 |
| `Kp, Kd, Ki` | 内环 PID | 先做 `steer → 航向角速率` 的阶跃响应，量出死时间与时间常数，再定 |
| 死区宽度 | 转向死区 | 由「池宽 − 鱼宽」反推上限 |
| 速度档位 | 直道 / 弯角 / 恢复 | 与漏检率联合标定 |
| `body_length` | 鱼体长度 | 实测（终点「全身进入」用） |

- 【设计】整定阶梯：**先仿真（带死时间的一阶模型）粗调 → 再水池测阶跃响应 → 最后调巡线增益**。跳过第一步会在水池里浪费调试窗口
- 【设计】每次整定必须记录「哪套参数 + 什么现象」，写进 [logs](../logs/README.md)。参数散落在代码里、改完不记录，是反复走回头路的主因

## 实测（合成场地，2026-09-25）

代码落在 `src/bionic_fish/control.py` 与 `fsm.py`。以下结论来自闭环仿真，**受制于占位动力学**（`plant.py`，全部 `【待验证】`），所以是「结构对不对」的证据，不是「参数好不好」的证据。

### 外环增益必须是 1.0，不能更大

直觉上把 `k_lateral` 调到 2.0 会更"跟得紧"，实测是错的：前视距离 89.6px 时，`2.0 × atan2(e_y, L)` 在 `e_y > 35mm` 就撞上 `max_heading_cmd_rad = 0.6`，而 35mm 属于正常跟踪误差范围。结果是**控制器长期饱和**——正是参考项目 `pipe1_fast` 的毛病（它的增益在画面宽度 12.5% 以外全部打满）。纯追踪的几何正确值就是 1.0：`atan2(e_y, L)` 本身就是指向前视点的角度。

### 弯角判据：`confidence` 可靠，`curvature` 只在最后一刻有用

沿上边直道逼近 s=2000 的直角（车体航向保持正东）：

| x (mm) | confidence | curvature (rad/row) |
| --- | --- | --- |
| 1800 | 0.93 | -0.00001 |
| 2300 | 0.92 | -0.00002 |
| 2450 | 0.61 | -0.00062 |
| 2485 | 0.52 | -0.00601 |

第二条弯角（s=3000，车头朝西）同样：confidence 0.97 → 0.50。**两个弯角都是单调塌陷**，而 curvature 只在最后 50mm 才抬头。所以判据用 `confidence` 为主、`curvature` 确认。

我也试过用「灯带远端偏离拟合直线」的方向（`branch_px`）来判断弯向：**不可用**。在需要它的位置它恒为 0（前向四分之一的可用行少于 3 行）。所以弯向目前取自赛题图的箭头（两个弯都是右转），标 `【事实】` 于 `FsmParams.corner_turn_sign`，并在注释里写清：若现场布局不同，退路是**限时双向搜索**。

### 弯角期间必须保留前进速度

`forward_corner` 一开始设成 1495（略低于中位，几乎停住）。在「转向权限随速度缩放」的欠驱动模型下这是设计错误：几乎停住的车**几乎转不动**，转弯必然超时。改成 1525（明显慢于巡航 1560，但仍有实速）后弯角阶段从 100 帧降到 62 帧。

### 转弯的四个结构性结论（都已实现并有测试）

弯角是整套算法里最难的一块，因为**灯带一旦离开视野就没有航向参考**。参考项目用纯开环定时转弯（无法适应电池/水流）。这里改成「提交方向、按角度或时限终止」，过程中修掉四个结构性问题——**每一个都曾让车体跑不完路线**：

1. **内环航向符号反了**（最严重，潜伏了两轮）。`e_theta` 是「灯带方向 − 车体航向」，是**灯带相对车体**的量；所以车体要达到的航向是「灯带方向 + 纯追踪修正」，误差应写 `e_theta + e_theta_d`。写成看起来更自然的 `e_theta_d − e_theta` 会让航向环变成**正反馈**：车头偏右反而被命令继续右转。**这个错误在「直道 + 横向偏置」的测试里完全看不出来**——那里 `e_theta` 恒为 0，两种写法数值相同。改成正确的和式后，全程横向误差从 48–73px 降到 1.4–12px。
2. **弯角必须独立于状态推进**。灯带在 90° 弯的中途必然消失；如果丢线就把状态切走、顺带停掉弯角判据，那么**终止转向的唯一机制会在最需要它的时候失效**（车体一直转，转到撞墙）。现在弯角用 `_bend_active` 独立跟踪，跨状态继续。
3. **有航向源时不允许「重新看见灯带」提前结束弯角**。弯角处灯带在画面里是个 L 形，行扫描拟合可能锁到上一段直道的残余，报出很小的 `e_theta`——实测这样会在**只转了 4.4°** 时就宣布弯角结束，然后径直冲过拐角。有航向源时只用「转够了角度」或时限终止。
4. **弯角结束后需要不应期**。刚转完 90° 时灯带仍在横向出画，宣布弯角的那个判据仍然成立；没有不应期就会立刻识别出**第二个弯**、再转 90°，开走。`corner_refractory_s` 就是为此。

### 弯角当前状态：一种起始条件能跑完全程

合成场地、占位动力学下的实测：

| 起始横向偏置 | 结果 |
| --- | --- |
| −30mm（偏左） | **跑完全程**（100%），8 个漏油点全部上报，29.3s，灯带可见率 0.93 |
| 0mm | 约 69% 后在推断触壁处终止 |
| +30mm | 约 69% 后在推断触壁处终止 |

也就是说：**第一个弯角已经稳定通过，第二个弯角的鲁棒性还取决于进入姿态**。

`tests/test_closed_loop.py::test_completes_from_a_left_offset` 把「能跑完」这一档钉成回归测试；`::test_completes_the_whole_course` 用 `@unittest.expectedFailure` 记录「所有起始条件都能跑完」尚未达成——它一旦通过会报 unexpected success，提醒同步删掉标记与本段。

剩下的三样都不是调参能补的：

1. **实测动力学**。现在提交转角长度与弯角增益都建立在 `plant.py` 的占位数字上，对着它们调参等于拟合虚构。
2. **第二个弯角的几何与弯向确认**。弯向目前取自赛题图的箭头（两个弯都是右转），`corner_turn_sign` 标了 `【事实】` 但未经现场确认。
3. **车体上真实可用的航向源**。没有它就只能走「限时双向搜索」的退路，而那条路要吃掉 150 秒预算里不少时间。
