# 排查手册

> 入口索引与工作约定在仓库根目录 [`AGENTS.md`](../../AGENTS.md)；本文件是 `.dsh/agents/` 知识库的一部分。
> 红线见 [`invariants.md`](invariants.md)（尤其第 10 条：先拿证据再改代码）。

**本文件状态：`【设计】`**——流程已定，尚未有真实故障记录。首次实战后回来补「实际根因」。

> [!CAUTION]
> **本文件大部分内容是 v0.1 的排查路径，v2 里对应的机制已经不存在。** 三条现状必须先知道，否则会照着不存在的日志去查：
> 1. **没有三道闸、没有闸门计数器、没有 `ReportEvent`**（都在 2026-10-02 的线性重写里删了）。§3 里「被闸掉了」这一分叉**现在无法从日志区分**——`find_black_dot` 内部的横向门控与形状窗口拒掉一个候选，和「根本没看见」在观测上长得一样（[architecture.md](architecture.md) 第 133 行的自认）。
> 2. **没有落盘、也没有可视化调试界面**（`grep imshow|imwrite|VideoWriter|logging` 在 `src/`+`sim/` 零命中）。下面「证据清单」里的六项**今天一项也产不出来**。
> 3. 现行状态名是 `FOLLOW` / `TURN` / `SEARCH`（找线）/ `FINISH`，四个；没有 `LINE_LOST` / `CORNER` / `ALIGN`。
>
> 也就是说：**先补落盘与可视化，这份手册才用得上**（[backlog.md](../../backlog.md) 已记）。

## 第一步：先分叉，不要先改参数

现场任何异常，先回答一个问题：**是「看不见」、还是「判错了」、还是「控不住」？**

```
现象
 ├─ 灯带看不到 / 时有时无           → §1 视觉-灯带
 ├─ 看到了但走不直、画龙、跑偏      → §2 控制
 ├─ 真实漏油点没上报                → §3 漏检
 ├─ 不该报的报了                    → §4 误报
 ├─ 弯角过不去 / 冲出灯带           → §5 弯角
 ├─ 提前停 / 到终点不停             → §6 起终点
 └─ 语音没播 / 录像里看不到信号     → §7 上报与播报
```

**证据清单（缺一项就不要下结论）**：

| 证据 | 用途 |
| --- | --- |
| 原始帧（连续 ≥2s） | 判断「画面里到底有没有」——这是唯一能回答「算法不行」还是「图像不行」的材料 |
| 增强帧 + 分割掩膜 | 判断分割阈值是否合适 |
| 中心线拟合结果叠加图 | 判断是「没检测到」还是「拟合歪了」 |
| 三道闸逐条判定日志 | 判断漏检 / 误报卡在哪一闸 |
| 状态机轨迹（状态 + `s` + `e_y` + `e_theta` + 指令，带时间戳） | 判断是判定问题还是控制问题 |
| 端到端延迟实测值 | 排除延迟导致的相位滞后 |

## §1 视觉：灯带看不到 / 时有时无

| 检查 | 判据 |
| --- | --- |
| 曝光是否过曝 | 灯带整片饱和成白块 → 阈值分割失效、游程中点漂移。降曝光或改用梯度特征 |
| 白平衡 / 色偏 | 湖蓝底被水吸收偏色后与灯带在 HSV 上不再可分 → 重建分割条件 |
| 水面反射 / 焦散 | 出现额外亮斑 → 靠形状先验（宽度一致性）剔除，或加偏振 |
| 灯带被黑贴片遮挡 | 游程中断 → 检查闭运算核大小与跨缺口拟合是否生效 |
| 相机离底过低 | 按 [hardware](hardware.md) 的视场表反查：视场宽度是否覆盖不了两个灯带间距 |
| 鱼体姿态导致相机看偏 | 叠加 IMU 姿态看是否在俯仰 / 侧倾时丢线 |

**不要**直接放宽亮度阈值来「修掉」丢线——那会把水面反光和白色标记放进来（[不变量 10](invariants.md)）。

## §2 控制：走不直、画龙、跑偏

| 现象 | 最可能的原因 | 处理 |
| --- | --- | --- |
| 低频大幅左右摆 | 外环增益过高 / 前瞻距离太近 / 端到端延迟大 | 加大前瞻距离（受视场限制）、降 `k_y`、补延迟 |
| 高频小幅抖 | 死区太小 / 内环微分噪声大 / 灯带中心线逐帧跳变 | 加死区、对 `e_theta` 低通、对中心线做时间平滑 |
| 恒定侧向漂移 | 死区太大 / 推力不对称 / 相机安装偏角未标定 | 标定相机安装角；先修死区再看推力 |
| 起步就冲一边 | **符号错了**（[不变量 1](invariants.md)）或 `valid=false` 被当成 0（[不变量 3](invariants.md)） | 先查符号与 `valid`，再怀疑参数 |
| 过弯后长时间过冲 | 内环积分 windup | 关积分或加抗饱和 |

## §3 漏检（真实漏油点没上报）

按顺序排查，**每一步都要有日志证据**：

1. `find_black_dot` 返回的 `Dot` 里有没有这个点？→ 没有 = **视觉没检测到**（§3a）；有 = 被上游拒掉（§3b）
2. §3a 视觉没检测到：对比度不足（贴片反光、被水雾遮挡）、尺寸超出面积窗口（标定错，看 `area_ratio_lo/hi`）、`blackhat_threshold` 太高 → 落盘该帧核对
3. §3b 被拒掉——**v2 只有两处能拒**，按顺序看：
   - `find_black_dot` 内部的**横向门控**（`max_lateral_offset_frac`）与形状/尺寸窗口：被它拒掉时**没有任何痕迹**，这是当前最大的可诊断性缺口
   - 上报条件：`dot.v > report_row`、`reports < max_reports`、以及 `in_dot` 布尔是否卡住
4. 都通过但没上报：检查 `report_row` 是否标错（它随相机安装俯仰变）、`max_reports=8` 是否已被干扰点吃满（**实测默认配置 8 次里只有 5 次命中真点**，见 [vision](vision.md)）

## §4 误报（不该报的报了）

按危险度从高到低查（清单见 [reporting](reporting.md#误报来源清单按危险程度)）：

| 检查 | 判据 |
| --- | --- |
| 是不是起终点黑带 | v2 **没有实现「起终点优先」规则**（[不变量 6](invariants.md)）：黑带只能靠 `tape_max_grey` / `tape_width_px_*` 与标记区分，没有任何一处逻辑把「在起终点附近」的暗斑排除在候选之外 |
| 是不是误识别点 | 把该候选的 `Dot.val` 打出来与标定值对比；判不了 → 回到 [vision](vision.md) 的判别特征表，这是最高优先级问题。v2 **只有 `dot_val_max` 一个旋钮** |
| 是不是阴影 / 焦散 | 看该候选在连续帧中是否随姿态 / 光照闪动（真标记应稳定且随接近单调变大）。注意**管顶高光带与两侧暗边是几何必然**，不是偶发噪声（[hardware](hardware.md)） |
| 是不是重复上报同一点 | 看 [main.py](../../src/bionic_fish/main.py) 第 4 节的 `in_dot` 复位条件（黑点是否回到了画面上半），**不是**加大冷却时间——v2 没有冷却期这个参数（[不变量 4](invariants.md)） |
| 延迟导致提前触发 | v2 **没有触发提前量参数**（上报就是「越过 `report_row` 就报」）。要补偿得先新增字段 |

## §5 弯角过不去

1. 先确认**弯角是否被识别**：`curvature` 是否超阈值、是否进入了 `CORNER` 状态
2. 若没识别 → 中心线拟合在弯角处被平滑掉了 → 减小拟合窗口 / 改用分段拟合
3. 若识别了但没转过去 → 降速不够或转向饱和时间不够 → 弯角速度档位再降，转向偏置保持时间加长
4. 若转过去但冲出灯带 → 恢复逻辑（§2 的画龙）与弯角开环段的衔接有问题
5. 【待验证】弯角半径未知：若实测最小转弯半径 > 灯带可用宽度，则**物理上过不去**，必须改平台或改策略（[strategy](strategy.md) 决策门）

## §6 起终点识别不到 / 提前停

| 现象 | 可能原因 |
| --- | --- |
| 到终点不停 | 黑带被当成普通暗斑（走了 `find_black_dot` 通路而不是 `is_tape()`）；或黑带宽度 / 对比度不足（`tape_*` 没标定）；或 `elapsed > finish_min_run_s` 这个前置条件没满足 |
| 起点就停 | 起点黑带被 `is_tape()` 认成终点线——v2 唯一的防线是 `finish_min_run_s = 20s`（[不变量 6](invariants.md)） |
| 停在终点区外 | `finish_creep_s` 没标定，或制动距离估算不足（「全身进入」按实测鱼体长度 + 制动距离定） |

## §7 上报与播报

| 现象 | 检查 |
| --- | --- |
| 报了但语音没播 | [`__main__.py`](../../src/bionic_fish/__main__.py) 构造 `Annunciator.for_host(p)` 时**没有传 `speaker`** ⇒ `speaker=None` ⇒ 真机上**永远不发声**（[不变量 5](invariants.md)）。先接一个 TTS 实现，再查 `speech_enabled` |
| 语音被环境噪声掩盖 | 音量 / 音调；有没有和蜂鸣器声重叠 |
| 录像里看不到声光信号 | 光强、颜色与白管反光的区分度、朝向、持续时长（`light_hold_s` / `buzzer_hold_s`）；**回看 3 个机位的录像逐点确认**（`【事实】`视频中无法辨别则该得分点无效） |
| 播报内容听不清 | 短语是否过长；改为「第 N 点」这类短句 |

## §8 系统层

| 现象 | 检查 |
| --- | --- |
| 掉帧 / 算力不够 | 相机采集是否「最新帧覆盖」而非排队（v2 **没有实现**：`Camera.read()` 是阻塞读）；标记检测是否已降频（v2 **没有实现**：每帧全跑）；落盘是否阻塞了控制环（v2 没有落盘） |
| 时间戳跳变 | 时钟源是否统一（[不变量 1](invariants.md)）：v2 用 `time.monotonic`，来自帧源 |
| 记录缺失导致无法复盘 | **v2 完全没有记录**——这条现在是「必现故障」而不是疑点，见文件开头的 CAUTION |
