# 排查手册

> 入口索引与工作约定在仓库根目录 [`AGENTS.md`](../../AGENTS.md)；本文件是 `.dsh/agents/` 知识库的一部分。
> 红线见 [`invariants.md`](invariants.md)（尤其第 10 条：先拿证据再改代码）。

**本文件状态：`【设计】`**——流程已定，尚未有真实故障记录。首次实战后回来补「实际根因」。

## 第一步：先分叉，不要先改参数

现场任何异常，先回答一个问题：**是「看不见」、还是「判错了」、还是「控不住」？**

```
现象
 ├─ 灯带看不到 / 时有时无           → §1 视觉-灯带
 ├─ 看到了但走不直、画龙、跑偏      → §2 控制
 ├─ 真实漏油点没上报                → §3 漏检
 ├─ 不该报的报了                    → §4 误报
 ├─ 弯角过不去 / 冲出灯带           → §5 弯角
 ├─ 提前停 / 到终点不停             → §6 起终点
 └─ 语音没播 / 录像里看不到信号     → §7 上报与播报
```

**证据清单（缺一项就不要下结论）**：

| 证据 | 用途 |
| --- | --- |
| 原始帧（连续 ≥2s） | 判断「画面里到底有没有」——这是唯一能回答「算法不行」还是「图像不行」的材料 |
| 增强帧 + 分割掩膜 | 判断分割阈值是否合适 |
| 中心线拟合结果叠加图 | 判断是「没检测到」还是「拟合歪了」 |
| 三道闸逐条判定日志 | 判断漏检 / 误报卡在哪一闸 |
| 状态机轨迹（状态 + `s` + `e_y` + `e_theta` + 指令，带时间戳） | 判断是判定问题还是控制问题 |
| 端到端延迟实测值 | 排除延迟导致的相位滞后 |

## §1 视觉：灯带看不到 / 时有时无

| 检查 | 判据 |
| --- | --- |
| 曝光是否过曝 | 灯带整片饱和成白块 → 阈值分割失效、游程中点漂移。降曝光或改用梯度特征 |
| 白平衡 / 色偏 | 湖蓝底被水吸收偏色后与灯带在 HSV 上不再可分 → 重建分割条件 |
| 水面反射 / 焦散 | 出现额外亮斑 → 靠形状先验（宽度一致性）剔除，或加偏振 |
| 灯带被黑贴片遮挡 | 游程中断 → 检查闭运算核大小与跨缺口拟合是否生效 |
| 相机离底过低 | 按 [hardware](hardware.md) 的视场表反查：视场宽度是否覆盖不了两个灯带间距 |
| 鱼体姿态导致相机看偏 | 叠加 IMU 姿态看是否在俯仰 / 侧倾时丢线 |

**不要**直接放宽亮度阈值来「修掉」丢线——那会把水面反光和白色标记放进来（[不变量 10](invariants.md)）。

## §2 控制：走不直、画龙、跑偏

| 现象 | 最可能的原因 | 处理 |
| --- | --- | --- |
| 低频大幅左右摆 | 外环增益过高 / 前瞻距离太近 / 端到端延迟大 | 加大前瞻距离（受视场限制）、降 `k_y`、补延迟 |
| 高频小幅抖 | 死区太小 / 内环微分噪声大 / 灯带中心线逐帧跳变 | 加死区、对 `e_theta` 低通、对中心线做时间平滑 |
| 恒定侧向漂移 | 死区太大 / 推力不对称 / 相机安装偏角未标定 | 标定相机安装角；先修死区再看推力 |
| 起步就冲一边 | **符号错了**（[不变量 1](invariants.md)）或 `valid=false` 被当成 0（[不变量 3](invariants.md)） | 先查符号与 `valid`，再怀疑参数 |
| 过弯后长时间过冲 | 内环积分 windup | 关积分或加抗饱和 |

## §3 漏检（真实漏油点没上报）

按顺序排查，**每一步都要有日志证据**：

1. `MarkerCand` 里有没有这个点？→ 没有 = **视觉没检测到**（§3a）；有 = 被闸掉了（§3b）
2. §3a 视觉没检测到：对比度不足（贴片反光、被水雾遮挡）、尺寸超出面积窗口（标定错）、极性判断反了（在黑底上）→ 落盘该帧核对
3. §3b 被闸掉：逐闸看
   - 闸 1 几何门控：是否因与灯带中心线距离超限被否 → 说明「标记在灯带上」的先验过强
   - 闸 2 时序确认：确认帧数 `N` 是否超过标记在视野中停留的帧数 → **提速或降 `N`**，二者与 [control](control.md) 的速度档位联动
   - 闸 3 去重：是否被前一个点的轨迹错误吸收了 → 检查轨迹关联的横向 / 里程门限
4. 都通过但没上报：检查「**重合时刻**」预测是否已经错过（确认完成时标记已移出视野）

## §4 误报（不该报的报了）

按危险度从高到低查（清单见 [reporting](reporting.md#误报来源清单按危险程度)）：

| 检查 | 判据 |
| --- | --- |
| 是不是起终点黑带 | 报的位置若落在黑带附近 → 闸 1 的「起终点优先」规则没生效（[不变量 6](invariants.md)） |
| 是不是误识别点 | 把该候选的判别特征打出来，与标定规则对比；若判别不了 → 回到 [vision](vision.md) 的判别特征表，这是最高优先级问题 |
| 是不是阴影 / 焦散 | 看该候选在连续帧中是否随姿态 / 光照闪动（真标记应稳定且随接近单调变大） |
| 是不是重复上报同一点 | 检查闸 3 的轨迹身份，而不是加大冷却时间（[不变量 4](invariants.md)） |
| 延迟导致提前触发 | 触发点补偿量是否用了实测延迟 |

## §5 弯角过不去

1. 先确认**弯角是否被识别**：`curvature` 是否超阈值、是否进入了 `CORNER` 状态
2. 若没识别 → 中心线拟合在弯角处被平滑掉了 → 减小拟合窗口 / 改用分段拟合
3. 若识别了但没转过去 → 降速不够或转向饱和时间不够 → 弯角速度档位再降，转向偏置保持时间加长
4. 若转过去但冲出灯带 → 恢复逻辑（§2 的画龙）与弯角开环段的衔接有问题
5. 【待验证】弯角半径未知：若实测最小转弯半径 > 灯带可用宽度，则**物理上过不去**，必须改平台或改策略（[strategy](strategy.md) 决策门）

## §6 起终点识别不到 / 提前停

| 现象 | 可能原因 |
| --- | --- |
| 到终点不停 | 黑带被当成普通暗斑（走了标记通路而不是 `CrossObs`）；或黑带宽度 / 对比度不足；或状态机的前置条件（已过弯角 / `s` 超阈值）没满足 |
| 起点就停 | 终点线的接受条件没加状态机上下文（[不变量 6](invariants.md)） |
| 停在终点区外 | 「全身进入」的续行距离 `body_length + margin` 没标定，或制动距离估算不足 |

## §7 上报与播报

| 现象 | 检查 |
| --- | --- |
| 报了但语音没播 | 语音是否真的订阅了 `ReportEvent`（[不变量 5](invariants.md)）；播报队列是否被新事件覆盖 |
| 语音被环境噪声掩盖 | 音量 / 音调；有没有和蜂鸣器声重叠 |
| 录像里看不到声光信号 | 光强、颜色与灯带白光的区分度、朝向、持续时长；**回看 3 个机位的录像逐点确认**（[事实] 视频中无法辨别则该得分点无效） |
| 播报内容听不清 | 短语是否过长；改为「第 N 点」这类短句 |

## §8 系统层

| 现象 | 检查 |
| --- | --- |
| 掉帧 / 算力不够 | 相机采集是否「最新帧覆盖」而非排队；标记检测是否已降频；落盘是否阻塞了控制环 |
| 时间戳跳变 | 时钟源是否统一（[不变量 1](invariants.md)） |
| 记录缺失导致无法复盘 | 落盘是否在控制环之外异步进行；容量是否按 150s + 调试时间预留 |
