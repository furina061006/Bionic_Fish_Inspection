## 视觉要回答的四个问题

| # | 问题 | 输出 | 用于 |
| --- | --- | --- | --- |
| 1 | 灯带在哪、朝哪 | `LineObs{e_y, e_theta, curvature}` | 巡线控制 |
| 2 | 路线上有没有深色圆斑 | `MarkerCand[]` | 漏油点上报 |
| 3 | 眼前这条黑带是不是起终点线 | `CrossObs` | 状态迁移、制动 |
| 4 | 一像素等于多少毫米 | 标定参数 | 上面三项的物理量换算 |

## 第 1 条纪律：增强帧只给人看，检测跑原始帧

- 【设计】水下图像需要增强（水吸收红光、后向散射抬升黑电平、光照不均），但增强会**改变灰度关系**，而「黑圆斑比周围暗多少」正是检测所依赖的量。因此：
  - 增强只用于**人看 / 落盘 / 报告插图**，不喂给检测与决策
  - 检测在原始帧上做，用**局部归一化**（局部均值 / 局部对比度）而不是全局拉伸来获得光照不变性
- 【设计】排查时必须能同时落盘 `raw` 与 `enhanced` 两帧，否则无法区分「算法看不见」和「画面本来就看不见」（[troubleshooting](troubleshooting.md)）

## 图像增强（可视化用）

- 【待验证】方法候选，按代价递增：
  1. 灰度世界 / 简单白平衡 + CLAHE（限制对比度自适应直方图均衡）——代价最低，先用它
  2. 暗通道先验去雾（DCP）——散射重时有效，但在浅水近距离场景收益未知且算力高
  3. 基于物理模型的水下成像反演——参数多、需要标定，暂不引入
- 【待验证】水面反射与焦散（caustics）在 260mm 浅水里可能比水体本身更严重；去反射属于预处理还是靠检测器的空间先验解决，未定

## 灯带提取与中心线

**物理先验**（决定方法选择）：

- 【事实】LED 灯带**自发光**，在图像里应是高亮度、低饱和度（近白）的细长条
- 【事实】池底是湖蓝色涂层：色相集中在蓝区、饱和度明显高于灯带
- 【设计】灯带宽度在图像中**近似恒定**（除弯角与透视缩放），这是极强的形状先验

**流程（设计）**：

```
原始帧
 → ROI 裁剪（只看中下方与灯带相关的区域，省算力、抗干扰）
 → 分割：HSV/ Lab 双条件 —— 亮度 > T_v  且  饱和度 < T_s（湖蓝底被排除）
 → 形态学去噪（开运算去散点，闭运算补灯带上的暗斑缺口）
 → 中心线：逐行扫描取灯带像素游程的中点 → 折线
 → 鲁棒拟合（RANSAC / 加权最小二乘）→ 直线或低阶多项式
 → 输出各行 e_y 与切线角 e_theta
```

- 【设计】**逐行扫描**优于骨架化：游程中点天然对灯带左右边缘的噪声对称，且行与行独立、易并行、易诊断
- 【设计】扫描方向按「灯带在图像中近似竖直」处理（下视相机 + 鱼体大致沿灯带前进）。若实测鱼体与灯带夹角大，需要改成沿主方向扫描
- 【设计】前瞻点取图像上方约 70%–85% 高度处的行，而不是最近的一行：等效于 Pure Pursuit 的前视，能显著抑制欠驱动系统的振荡（[control](control.md)）
- 【待验证】视场只有约 0.2–0.5m 宽（[hardware](hardware.md)），前瞻距离的**上限由视场决定**，不是想取多远就取多远

**失败模式（必须能被检测到，而不是静默给出错误值）**：

| 现象 | 原因候选 | 处理 |
| --- | --- | --- |
| 整帧无灯带像素 | 离开灯带 / 曝光过暗 / 灯带被遮挡 | `LineObs.valid = false`，进 `LINE_LOST` |
| 白色斑块被当成灯带 | 水面反光、气泡、误识别点若为白色 | 形状过滤：宽度突变、面积过大、不连贯 |
| 灯带被断开 | 灯带上压着黑色漏油点贴片 | 闭运算 + 跨缺口拟合直线（不能因为一个点就判丢线） |
| 出现两条候选带 | 弯角处同时看到横竖两段 | 取与上一帧方向一致的那条；弯角判据用 `curvature` |
| **锁到管顶高光带** | 白色圆柱管在光源下沿长度方向出现镜面高光，**比管壁更亮且窄得多** | 宽度窗口以**真实管径**为中心（`strip_width_mm`）；绝不做「这一行最亮的就是管道」 |
| **管道两侧暗边被当成标记** | 圆柱边缘的阴影形成长条暗带 | 暗斑判据要求近圆 + 尺寸匹配 + 落在中心线附近 |
| 水面焦散暗纹 | 波纹把光聚焦成移动的暗纹 | 帧间一致性：真标记单调增长且平滑，焦散不满足 |

> [!IMPORTANT]
> `valid=false` 与 `e_y=0` 是两件完全不同的事。**绝不能用 0 表示「没看到」**——控制律会把「没看到」当成「已经对准」，直接撞边界（[不变量 3](invariants.md)）。

### 实物是白色圆柱管道，不是 LED 灯带

- 【事实】队内确认（2026-10-02）：路线实物是**白色圆柱形管道**；原文 p3 写的是「池底 LED 灯带」（两处出处的对照见 [competition](competition.md) 的「实物补充」一节）
- 【推论】两者成像不同：灯带**自发光**——不依赖环境光、没有阴影、关灯也亮；白管**被动反光**——依赖照明、有高光带与两侧阴影、水质变浑就变暗。**不能照搬参考项目的灯带阈值**
- 【事实】代码里沿用参考项目的 strip 命名（`StripTracker` / `StripParams`），指的是同一样东西；改名要动很多处，暂不改
- 【待验证】因此**是否需要主动补光**成为未决项（[hardware](hardware.md)）；分割方法（`tophat` / `bright_low_sat`）也必须在真实白管上重选——默认的 `tophat` 是「亮**局部**结构」，对反光物体仍然合理，但阈值全要重标

## 标记检测（漏油点候选）

- 【事实】漏油点是 ⌀3cm 黑色圆形贴片，沿灯带路线随机布置
- 【设计】黑圆在亮灯带上是**暗底反转**目标，在浅蓝池底上是**高对比暗斑**——两种情形对比度都够，所以**检测本身不难，难的是判别与去重**
- 【设计】主方法：**黑帽变换（闭运算 − 原图）** 增强小于结构元的暗斑 → 自适应阈值 → 连通域 → 按下列特征过滤：

| 特征 | 依据 | 状态 |
| --- | --- | --- |
| 像素面积 | 3cm 圆的投影像素面积，由标定给出窗口 | 【待验证】需标定 |
| 圆度 / 凸度 | 规定为「圆形标识」 | 【事实】原文说是圆形 |
| 长宽比 | 圆形 → 接近 1；黑色胶带 → 狭长 | 【设计】 |
| 与灯带中心线的距离 | 标记布置在路线上 | 【设计】 |
| 局部对比度极性 | 目标比周围暗 | 【设计】 |
| 帧间一致性 | 真标记随鱼前进由远及近、尺寸单调增长、横向位置平滑 | 【设计】 |

- 【待验证】其它暗目标同样是误报来源，必须逐一验证：**起终点黑色胶带**（最危险，也是黑的）、鱼体自身与气泡的阴影、池底杂物、灯带缺口、水面焦散暗纹

> [!IMPORTANT]
> 起终点黑带与漏油点都是「黑色的东西」。**靠视觉单帧区分不可靠，必须叠加状态机上下文**：在起终点区附近出现的暗带优先解释为分界线，不作为漏油点候选（[不变量 6](invariants.md)）。

## 漏油点与误识别点的判别

- 【事实】8 个漏油点是 ⌀3cm 黑色圆形；5 个误识别点也是 ⌀3cm 圆形；**原文没有给出两者的区分特征**
- 【推论】比赛既然设置「误识别点」并对其误报扣分，**两者在设计上必然可区分**；判据只是没写在赛题文件里
- 【待验证】具体靠什么区分，应在组委会提供的物料 / 现场实物中找
- 【待验证】调试窗口内必须逐项测的候选判别特征（按「便宜且稳」排序）：

| # | 候选特征 | 说明 | 代码现状 |
| --- | --- | --- | --- |
| 1 | **绝对暗度** | 漏油点被确认为**纯黑**，而检测用的黑帽是**相对**量：白管上纯黑圆与中灰圆都会产生大响应，任何相对阈值都分不开它们 | **已实现**（`discriminator = "darkness"`，用现成的 `MarkerCand.val`，不需要额外计算） |
| 2 | 颜色 / 色相 | 误识别点可能是红 / 黄 / 白等非黑色 | 已实现（`hue`） |
| 3 | 内部图案 | 实心 vs 有十字 / 字母 / 空心环 | 已实现（`pattern`，按填充率） |
| 4 | 相对管道的位置 | 漏油点在管道上，误识别点可能在管道旁 | 已实现（`position`） |
| 5 | 表面反光特性 | 哑光贴片 vs 亮面，在水下差异明显 | 未实现，需新增特征 |
| 6 | 尺寸差异 | 原文都写 3cm，但印刷可能有可测差异 | 未实现（`equiv_diameter_px` 已带，加规则即可） |

- 【事实】合成场地**单帧**实测（标记居中、两个观察方向）：漏油点 `val` = 46…60，误识别点 `val` = 122…137
- 【事实】但**跑完整场**再看，两个区间**重叠**。把 `val_band` 上界从 60 扫到 255：

| 上界 | 上报数（真值 8） | 被暗度拒掉的候选 |
| --- | --- | --- |
| 90 | 5 | 185 |
| 100 | 5 | 181 |
| 110 | 7 | 153 |
| **120** | **8** | 71 |
| 130 | 8 | 42 |
| 150 | 8 | 1 |

- 【推论】**单帧的 46…60 是取样不足造成的假象**：渲染器有横跨整帧的光照梯度，同一种标记出现在画面不同位置时，漏油点自己的 `val` 会爬到 120 附近——正好撞进误识别点的 122…137。**在这个渲染器里，绝对灰度分不开两者**
- 【待验证】这**不构成**关于真实管道的证据：真实纯黑贴片在白色管道上的区间可能窄得多。但它说明两件事：(a) 这条规则**必须在真实水池里标定**；(b) 值得再有一个**相对局部背景归一化**的暗度量，与绝对量并列比较
- 【设计】正因为目前没有可信的分界，`val_band` 默认**全收**（`0…255`）。默认配置下选择 `darkness` **不会**悄悄拒掉真漏油点——有测试守着这条（`test_darkness_discriminator_default_band_accepts_everything`）
- 【待验证】判别器这条线上**目前没有已证实可用的特征**。首选假设（绝对暗度）在渲染器里被否定，其余候选（色相 / 图案 / 位置）都需要实物才能试。这是 [backlog](../../backlog.md) 里 [#1]「第一风险」的现状
- 【设计】所有判别带（`hue_band_deg` / `fill_ratio_band` / `offset_band_frac` / `val_band`）默认都是**全收**。选择某个判别器**不会**在标定完成前悄悄拒掉候选——否则默认配置会变成「什么都不报」，而那种失败看起来像感知坏了

- 【设计】标定产出必须是一份**可判别的规则 + 阈值 + 留出样本上的验证结果**，写进 [operations](operations.md) 的标定记录，而不是「现场看着调」的临时值
- 【设计】兜底方案：若确实无法在单帧区分，则把判别推迟到**多帧轨迹 + 位置先验**，并**降低上报倾向**（漏检一个 `−5` 好过误报 `−3`，见 [reporting](reporting.md) 的阈值推导）——但这是降级方案，不是首选

## 起终点分界线

- 【事实】起终点使用黑色胶带作为分界线，位于距左池壁约 500mm 的竖直带（[competition](competition.md#路径几何俯视图)）
- 【设计】检测：横穿灯带、垂直于行进方向、宽度远大于漏油点的暗带
- 【设计】起点线与终点线外观相同，**只能靠状态机区分**：起航时忽略；完成至少一个 90° 弯角（或沿路径里程 `s` 超过阈值）之后才接受为终点线
- 【设计】收到 `CrossObs` 后不立即停机，要按「**全身进入**终点区」继续前进一段，距离 = 鱼体长度 + 余量，实测后填入（[control](control.md)）

## 标定

标定是全部物理量阈值的前提（[不变量 7](invariants.md)）。

| 标定项 | 方法 | 产物 |
| --- | --- | --- |
| 像素尺度 px/mm | 在已知相机高度下拍摄已知尺寸物（用 ⌀3cm 标记实物本身最直接） | `mm_per_px(h)`，含随高度变化的系数 |
| 相机安装高度与俯仰 | 直尺 / 已知几何体；或由灯带已知内缩 500mm 反推 | `h`, `pitch` |
| 镜头畸变 | 棋盘格标定板（若视场小可只标径向系数） | 畸变系数 |
| 灯带宽度先验 | 实测灯带在图像中的像素宽度范围 | `strip_width_px` 区间 |
| 标记像素面积窗口 | 由 px/mm 与 3cm 推出，再用实物验证 | `area_min`, `area_max` |
| 起终点带宽度 | 实测 | `cross_width_px` |
| 执行器符号与量程 | 给正 / 负指令看鱼怎么动 | 符号约定表 |

- 【设计】标定参数必须落在**一个带版本号的配置文件**里，并在日志里记录「用哪套参数跑的比赛」；散落在代码里的魔数一律不接受
- 【设计】标定流程与时间盒见 [operations](operations.md)（调试窗口只有 10 分钟 / 2 分钟）

## 验证方式

- 【设计】离线：录制真实水池视频（含 8 + 5 两类标记），对每一帧跑管线，统计
  - 灯带：`valid` 帧占比、弯角处丢线次数
  - 标记：按标注算查全 / 查准；**分别统计漏油点与误识别点的误判率**（后者才是扣分来源）
  - 起终点：误触发次数（起点被当终点 = 直接判负）
- 【设计】在线：实时叠加可视化（增强帧 + 掩膜 + 中心线 + 候选框 + 当前状态 + 三个闸的判定结果），这是现场唯一能看懂的调试界面
