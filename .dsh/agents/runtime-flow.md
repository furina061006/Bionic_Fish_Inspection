# 代码结构：鱼在池子里做的事

> 入口索引与工作约定在仓库根目录 [`AGENTS.md`](../../AGENTS.md)。
> 本文件讲**代码怎么组织、一帧按什么次序跑、哪些坑不能踩回去**。
> 只想知道「怎么跑」看 [`README.md`](../../README.md)；只用读代码看 `src/bionic_fish/main.py`。

**本文件状态：以 `【事实】` 为主**，内容由 `src/` 现行代码读出。行号会漂，**动手前先 grep**。

## 一、一句话

`main.py` 是一个循环，**从上往下读就是鱼的行为**。其余模块是被它调用的函数库，
只有想知道「这一步怎么算」时才打开。

比 v0.1（11 个模块 / 4517 行 / 每帧转一圈）短得多，也直得多。改动原因见
[logs/2026-10-02-linear-rewrite](../logs/2026-10-02-linear-rewrite.md)。

## 三、核心与两个壳之间只有两个口

【事实】`main(camera, link, p)` 只要求两件事：

```
帧源   camera.read()            -> (时间戳, 帧)  或 None
出口   link.send(yaw, forward)                   两个 PWM
```

【事实】**核心不知道自己在哪跑**。实机塞 `Camera` + `MavlinkLink`，仿真塞
`FakeCamera` + `SimLink`。逻辑一行不改 —— 参考项目做不到这件事，因为它把
`cv2.VideoCapture` 和全局 MAVLink 写死在函数里。

时间戳由**帧源**给（实机是 `time.monotonic`，仿真用虚拟时钟），核心不自己取当前
时间。所以仿真是确定性的，而且跑得比实时快。

## 四、一帧的 7 步

【事实】`main.py` 的 `while True`，7 步。**代码里的节标记与下表逐字对应**，所以可以直接 grep 定位：

```sh
grep -n '^        # =====' src/bionic_fish/main.py
```


| # | 步 | 做什么 |
| --- | --- | --- |
| 1 | **四条硬终止** | 超时 / 撞壁 / 未启动 / 脱线。放最前面，任何状态逻辑都绕不过去 |
| 2 | 看 | `find_white_pipe` → `find_black_dot` → `is_tape` |
| 3 | 撞壁计数 | 横向偏差持续饱和 → 计一次接触 |
| 4 | 上报 | 黑点越过触发行且不在「已报」状态 → 亮灯 + 播报 |
| 5 | 判 | 巡线 / 转弯 / 找线 / 终点 |
| 6 | 打舵 + 发 | 舵量按状态选，前进量按状态选，各发一个数 |
| 7 | 读下一帧 | `camera.read()`；返回 `None` 就结束 |

## 五、四条硬终止

【事实】全部来自赛题 PDF，**参考项目一条都没有**（它的主循环是 `while 1`）：

| 条件 | 出处 | 实现 |
| --- | --- | --- |
| 完全脱离路线 > 10 秒 | p2 | `lost_timeout_s` |
| 触碰池底/池壁满 3 次 | p2 | `wall_hit_limit`，无传感器时用「横向偏差持续饱和」推断 |
| 宣布开始后 30 秒未启动 | p2 | `start_timeout_s` |
| 超过 150 秒 | p6 | `run_timeout_s` |

【设计】**次序与条件都有意义**，这是踩出来的：

1. 「未启动」排在「脱离路线」**之前**
2. 而且脱线**只在鱼动过之后才算**（`if started and lost_since is not None`）

理由：没动过的鱼谈不上「脱离路线」，可一张空画面会让两条同时成立。若不这样，一条
从没启动的鱼会被记成「跑丢了」，**读日志的人会往错的方向查**。

【事实】「鱼动了没有」的门限 `started_forward_us` **必须远小于最小速度档与中位的
差**。丢线档是 `lost_slow - neutral = 50`；这个门限原本取 60，于是丢线后正在游动的
鱼被判成「从未启动」，30 秒后被误终止。现取 20。

## 六、上报：两个坑

【事实】逻辑只有几行：黑点越过 `report_row` 且不在「已报」状态 → 报一次。

【设计】**复位判据是「黑点回到车体前方」（行号 < 画面高的一半）**，两个错误的
写法都实测过：

| 错误写法 | 实测后果 |
| --- | --- |
| 等黑点**完全离开画面**再复位 | 13 个标记平均间距约 460mm，**小于相机视场约 400mm**，画面里常常同时有两个点 ⇒ **上直道 4 个真漏油点只报了 1 个** |
| 比上一帧**小一点**就复位 | 太松：一次瞬时误检就能把同一个点报第二遍 ⇒ 实测出现相隔 **14mm** 的两次上报 |

【事实】**已放弃的能力**：v0.1 有一套「最弱一环打分 + 阈值 `p > 3/8`」的置信度
判决，现在没有了。后果是**候选无条件上报**，实测（合成场地，居中起始）：

| 配置 | 上报 | 覆盖真漏油点 | 干扰点 |
| --- | --- | --- | --- |
| 默认（照参考项目：`dot_val_max=255` 全收，上限 8） | 8 | **5** | 3 |
| 全收，上限 13 | 12 | 8 | 3–4 |
| `dot_val_max=90`，上限 13 | 9 | **8** | **0** |

- 【推论】干扰点会**吃掉 8 次上报预算**，把后面的真漏油点挤掉 —— 这是「上限 8」与
  「全收」一起作用的结果
- 【待验证】`90` 是**渲染器**的值（它的干扰点外观是猜的灰圆）。真机必须用真实物料
  重量，见 [`vision.md`](vision.md) 的判别一节

## 七、转弯

【设计】固定舵量 + 慢速，**由时间戳判结束，不用阻塞 `sleep`**。参考项目用 `sleep`
几秒 —— 那几秒里 150 秒总计时也在走，丢线保护也失效。

【事实】保留了一条参考项目没有的认识：**「重新看见管道」不能立刻结束转弯**，必须先
转过 `corner_min_commit_s`。弯角处管道在画面里是个 L 形，行扫描拟合会锁到上一段直道
的残余，报出很小的航向误差 —— 实测只转了 **4.4°** 就会宣布弯角结束、径直冲过拐角。

【设计】转完有**不应期**：灯带横向出画这个判据在转完后仍成立，没有不应期会立刻识别
出第二个弯、再转 90°。

## 八、读代码的顺序

1. `src/bionic_fish/main.py` —— **全部**。读完就知道鱼干什么
2. `src/bionic_fish/params.py` —— 数字（想知道某个阈值哪来的看这里）
3. `drive.py` 的 `heading_error` —— 一处踩坑换来的符号约定，见它自己的 docstring
4. `vision.py` —— 只在怀疑「看错了」的时候读

**不要**先读 `params.py`（数字墙）或 `sim/`（你不跑仿真就不用看）。
