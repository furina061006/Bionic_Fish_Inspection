## 二、顺手抓到一个没用的导入

`main.py` 里 `import time` **一次都没用到** —— 所有时间都来自帧源给的时间戳，主循环从不
自己取时钟。这是那次"时间戳由帧源提供"的设计决定的：一旦核心不取时钟，`time` 就成了死
导入。**删掉。**

（同类检查也扫了别的模块：`numpy` 在 `camera.py`/`main.py` 里只出现在类型标注里，那不是
死导入 —— 它服务于类型检查器。）

## 三、拆函数 vs 分节：一次完整的取舍讨论

审阅者提议"拆成子函数"。讨论里定下了一条判断标准，以及一个**被否掉的方向**。

### 3.1 先纠正我自己上一轮的说法

我上一轮只证明了「不能全拆」，没回答「那怎么办」—— 那只对了一半。而且我拿 212 行说事时
把「整个文件」当成了「函数」：**实测 `main()` 是 157 行，其中真正的代码 109 行**。109 行
放在一个函数里，相对常见经验值（40–60 行）确实偏长，**审阅者的直觉是对的**。

### 3.2 「太大」有三种含义，解法完全不同

| 含义 | 症状 | 拆函数有用吗 |
| --- | --- | --- |
| 视觉太长 | 一屏放不下，滚动时丢上下文 | 有用，但**还有零代码改动的招** |
| 职责太多 | 一个函数做了 7 件事 | 这是标准解法 |
| 认知太重 | 读时要同时记住 13 个变量 | **不一定** —— 减少跨帧变量才管用 |

### 3.3 为什么"全拆"是亏的

**抽函数不减少总阅读量，它把"顺序"变成"接口"。当被抽出去的东西本身就是重点时，抽象是亏的。**

具体看那 8 分支：

```python
state = pick_state(pipe, dot, tape, state, elapsed, lost_since, bend_done_at, turn_started, p)
```

这一行读过去什么都不知道。你得跳过去读完 36 行，才知道「转弯」排在「丢线」前面 ——
**而那个顺序就是这条逻辑的全部价值**。抽出去之后它不在上下文里了。

四条硬终止同理：抽成 `_stopped(...)` 要传 5 个变量、返回 `Result | None`，签名比那 16 行难读。

### 3.4 定下来的判断标准（比"行数"好用）

> **看它有没有自己的私有状态。有私有状态的搬走，纯读纯写的留下。**

| 片段 | 私有状态 | 结论 |
| --- | --- | --- |
| 撞壁计数 | `sat_since` / `sat_counted` | 可搬 |
| 上报 | `in_dot` | 可搬 |
| 四条硬终止 | 无（只读已有变量） | 留下 |
| 8 分支状态判断 | 无（只写 `state`） | 留下 |
| 打舵 | 无 | 留下（里面藏着"丢线不重新赋值 `yaw`"这条防线） |

【设计】这条标准的依据是：**有私有状态的东西是一个自足的机制，搬走之后调用方只需要知道
它"数了几次"；没有私有状态的东西是决策本身，搬走就等于把决策藏起来。**

### 3.5 被否掉的方案

- **拆成七个步骤函数**（一步一个）—— 否掉：七步的长度差 10 倍（第 2 步 3 行、第 5 步 36 行），
  给 3 行的东西建函数是纯噪音
- **`main()` 只做三件事**（取帧 / 决策 / 发）—— 否掉：那正是 v0.1 的 `Runner._iterate`，
  历史已经证明它读不懂

### 3.6 选定：分节

零代码改动，只动注释与空行。

## 四、分节做了什么

- 每节统一成 `# ===== N. 名称 =====`，**说明集中写在节标题下面**，不再散在代码行之间
- 新增「准备」一节（`ann`/`pid` + 首帧 + 跨帧记忆）
- 模块 docstring 里放了一份「折叠后应该看到的样子」，对着它就能确认折叠有没有生效
- 行内只留 1~4 行的就近说明（例如转弯分支里「最短转弯时间」的来由）

**验证方式值得记一笔**：用 AST 比较改前改后的 `main()` 函数体。

```
main() 的语法树完全一致: True
```

注释不进 AST，所以这条为真就等于**代码一个字都没动**。比"跑一遍测试看看"强得多 ——
测试只覆盖被测的路径，AST 比较覆盖全部代码。

## 五、要如实说的代价：文件反而变长了

|  | 改前 | 改后 |
| --- | --- | --- |
| `main.py` 全文件 | 211 行 | **257 行** |
| `main()` | 157 行 | **199 行** |
| 其中真正的代码 | 109 行 | **109 行**（没变） |

原因：说明从"复用行内空间"改成"独占整块"。

**所以这是「折叠换长度」的交易**：展开看更长，折叠看只剩 8 个节标题 + 骨架。

【推论】**分节和抽函数有同一个性质 —— 都不减少总阅读量**，区别是分节把长度换给了
**可折叠性**，而折叠是编辑器免费提供的。所以同样要达到"看起来短"，分节比抽函数划算：
抽函数要付"顺序离开上下文"的代价，分节不用。

## 六、留下的选择

拆那两段私有状态的片段（`WallHits` / `Reports`）**还没做**，等审阅者先看看折叠效果：

- 做了的话：`main()` 代码 109 → 约 70 行，跨帧变量 13 → 8
- 代价：多两个类和它们的构造；`sat_since`/`sat_counted`/`in_dot` 从 main 的变量表里消失
  （**这是双刃的**：表短了，但"鱼的全部状态"不再一屏看全）
