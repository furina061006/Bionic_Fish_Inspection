## 二、`.dsh/` 与 `AGENTS.md`：这是什么，怎么用

这个仓库的文档不是「写给人看的说明书」，而是一套**让智能体和人都能在不读完所有东西的前提下正确动手**的结构。分三层，各回答一个不同的问题：

| 层 | 位置 | 回答 |
| --- | --- | --- |
| 索引 | `AGENTS.md` | **我该怎么在这儿干活** |
| 事实 | `.dsh/agents/` | **什么是真的** |
| 过程 | `.dsh/logs/` | **怎么变成现在这样的** |
| 待办 | `backlog.md` | **还缺什么、什么卡着它** |

### `AGENTS.md` 为什么必须叫这个名字

DSH 只自动加载两个**文件名**：`AGENTS.md` 与 `CLAUDE.md`（另加 `AGENTS.local.md` / `CLAUDE.local.md` 作为本机覆盖层）。依据在 `packages/context/agent-instructions/src/config.ts`：

```ts
const DEFAULT_INSTRUCTION_FILE_CANDIDATES = ['AGENTS.md', 'CLAUDE.md'] as const
```

所以：**不能改名叫 `agent.md`**（单数）。`AGENT.md`、`agents.md` 在整个代码库里**没有任何地方被引用**，改了它等于这份索引再也不进上下文——而且是**静默失效**，不会报错。

**位置同样决定作用域**：只有仓库根目录那一份是「项目级指令」（每轮都在上下文里）；放进 `.dsh/` 就只对那个目录生效。这就是索引留在根目录、细节才敢下沉的原因。

### `.dsh/agents/` 怎么用

它按主题拆开，**一个主题一个住所**。任何一条事实只在一个文件里定义，别处只链接。改动前按 `AGENTS.md` 的路由表读对应文档，改完**回来更新它**。

文档里的每句话都带状态标记，**这是这个仓库最重要的约定**：

| 标记 | 含义 | 能不能写进代码常量 |
| --- | --- | --- |
| `【事实】` | 赛题文件 / 官方规则 / **实测结果** | 可以 |
| `【设计】` | 本队已决定的方案 | 可以 |
| `【推导】` `【推算】` `【推论】` | 由事实算出 / 估算 / 推出的结论 | 可以，但假设要写出来 |
| `【待验证】` | 假设、未确认的接口、未测的数据 | **不可以** |

所以：**看到 `【待验证】` 就别把它当依据**，它多半在 [`backlog.md`](backlog.md) 里有一条对应的待办。反过来，如果你实测证伪了某条 `【待验证】`，**请把它改成 `【事实】` 或删掉**——永远不摘的 `【待验证】` 会让整份知识库失去可信度。

### `.dsh/logs/` 怎么用

日期日志是**当时的过程快照**。发现旧日志写错了、过时了，**不要改它的正文**——在当天的或新的日志里说明即可。日志里最有价值的通常不是结论，而是「中途改正过的地方」：那些是已经交过学费的地方。

### 维护节奏

> 先更新 `.dsh/agents/` 对应文档 → 再写 `.dsh/logs/` 开发日志 → 更新 `.dsh/logs/README.md` 索引。

改完文档跑一次链接校验：

```sh
python3 .dsh/tools/check-links.py .
```

它会把 fenced code block 里的示例剔掉再逐条解析相对链接与标题锚点，并**自动跳过 `.gitignore` 里根锚定的目录**（所以不会去校验 `reference/` 这个第三方树）。

## 三、系统架构：一句话 + 一张图

完整版（含**模块边界为什么切在这里**、**十条模块间耦合约束**）在 [`.dsh/agents/architecture.md`](.dsh/agents/architecture.md)。这里只给骨架：

```
相机帧
  → 感知 perception   这一帧看到了什么（不含任何策略）
  → 决策 reporting    该不该上报（轨迹关联 + 三道闸 + 概率判决）
  → 状态 fsm          跑到哪了、该快还是该慢（含四条硬终止）
  → 控制 control      给定目标怎么打舵（串级纯追踪）
  → 平台 platform     怎么发出去 / 怎么对外发信号
```

**边界切在「看得见 / 判得对 / 控得住」上，判据是排查时分得清哪一层错了。** 感知一旦顺手决定「该不该上报」，一次漏报就分不清是**没看见**还是**看见了被否决**——而那正是排查的第一分叉。

有三条耦合最容易被当成「两个独立模块」而踩掉，动手前务必看 architecture 那一节：

- **转向权限 ∝ 前进速度**（欠驱动尾鳍车没有侧推）：弯角把速度降到接近零 → **转不动**。
- **「重合」不能用里程判定**（没有里程计）：上报触发用固定图像行，行阈值来自标定。
- **像素阈值 ← 标定 ← 相机安装**：相机未定则全部尺寸阈值未定，所以代码里不许有未标定的尺寸常数。

## 四、代码结构

**先读 `src/bionic_fish/main.py`** —— 它是一个循环，从上往下读就是鱼在池子里做的事。
其余模块是被它调用的函数库，只在想知道「这一步怎么算」时才打开。

包名 `bionic_fish`，纯 Python，依赖 `numpy` + `opencv-python`（`pymavlink` + `pyserial` 只在真机路径用）。

| 文件 | 职责 | 关键点 |
| --- | --- | --- |
| `main.py` | **主循环。鱼的行为全在这里** | 一帧 7 步，第一条就是四条硬终止，任何状态逻辑绕不过去。它**不知道自己在哪跑** |
| `params.py` | 全部可调参数，默认值照参考项目；平的 YAML 覆写 | 一个 `Params` dataclass，没有 11 层抽象。`check()` 在加载期拒绝自相矛盾的配置 |
| `vision.py` | 看：`find_white_pipe` / `find_black_dot` / `is_tape` | top-hat 分割抗光照梯度；游程宽度窗口挡住管顶镜面高光带；黑带用**绝对暗度**（黑帽在亮结构边缘也会响应） |
| `drive.py` | `Pid`（实测 dt、显式抗饱和）+ 期望航向 + 限斜率 + **尾鳍合成** | 内环误差是 **`e_theta + 修正量`**，不是差 —— 写成差会让航向环变正反馈，而直道测试看不出来。`synthesize_tail_fin()` 把 `yaw + forward` 压成一个关节指令 |
| `fin.py` | 单关节尾鳍的**波形线程**：`(摆幅, 偏置)` → 串口 PWM | 主循环 15–30 fps 做不出 3 Hz 平滑尾摆，所以相位推进在独立线程（默认 100 Hz）。`open_serial` 打不开就抛，**没有「假装发送」兜底** |
| `link.py` | 出：`TailFinLink`（默认）+ `MavlinkLink` + `Annunciator`（灯 / 蜂鸣 / 播报） | 尾鳍只对外给 `send_tail_fin`（合成只在 `main.py` 一处）；飞控只开一条 MAVLink 连接、解锁校验 `COMMAND_ACK` |
| `camera.py` | 进：`Camera` | 两个口之一。时间戳用 `time.monotonic` |
| `__main__.py` | 实机入口：连接 → 解锁 → `main()` → **上锁** | `disarm` 放 `finally` 是安全要求；连接被拒直接退出，**不降级**（尾鳍后端也是） |

仿真壳在仓库根的 `sim/`，**不入包**：`arena.py`（合成场地）、`plant.py`（占位动力学）、
`harness.py`（假相机 + 假飞控）、`run_sim.py`（入口）。

### 这份实现是**参考实现**

`plant.py` 的全部动力学是占位值，`params.py` 的默认值多数照参考项目 —— **未必适配真机**。
对着 `plant.py` 调参等于拟合虚构。值得保留的是[四条硬终止](.dsh/agents/runtime-flow.md#五四条硬终止)、
「丢线不当成已对准」、以及 `drive.py` 的符号约定。

### 已经放弃的能力

v0.1 有一套「最弱一环打分 + `p > 3/8` 判决」的上报置信度。现在没有，**候选无条件上报**。
实测代价：干扰点会吃掉 8 次上报预算，把真漏油点挤掉（居中起始 8 次上报里 5 真 3 误 3 漏）。
把 `dot_val_max` 从 255 压到 90 可回到 8/8、零误报，但那个 90 是渲染器的值，
真机必须用真实物料重量。见 [runtime-flow](.dsh/agents/runtime-flow.md) 第六节。

## 五、怎么跑

环境是 conda 环境 `aquacore`（Python 3.10 + `numpy` + `opencv-python` + `PyYAML`）。
`pymavlink` 在这个环境里已装，但 **`pyserial` / `RPi.GPIO` / `onnxruntime` 没有**——所以本机只能跑到仿真与测试，连真飞控那条路都缺 `pyserial`（`pymavlink` 不依赖它）。

```sh
conda activate aquacore

# 可编辑安装一次。开发机（只跑仿真）：
pip install -e .
# 上位机 / 树莓派（要真的连飞控、点 GPIO）：
pip install -e ".[hardware,rpi]"

# 仿真跑一趟 —— 没有相机、没有鱼也能跑完
python -m sim.run_sim

# 换起始条件
python -m sim.run_sim --lateral-mm -30

# 用一份参数覆写跑（平的 YAML，键名就是 params.py 的字段名）
python -m sim.run_sim --config tank.yaml

# 实机（默认：单关节尾鳍，走串口直连下位机；需要真相机与下位机）
python -m bionic_fish --device /dev/ttyUSB0

# 实机（旧 MAVLink 飞控后端，仍保留但通道号未确认）
python -m bionic_fish --mavlink --device /dev/ttyACM0
# 注意：不要用 `bionic-fish` 这个控制台脚本，它指向一个不存在的函数（见 backlog.md）

# 跑测试（无需硬件）
python -m unittest discover -s tests

# 校验文档链接与锚点
python3 .dsh/tools/check-links.py .
```


**注意**：测试用标准库 `unittest`，**不是 pytest**。不要用 `python -m unittest tests/xxx.py` 那种写法——它会把 `tests/` 当包导入，而它不是包。

当前状态：**32 个测试通过**（18 条主循环逻辑 + 14 条尾鳍）。仿真下 0 与 ±30mm 三种起始条件都能跑完全程、8/8 上报。

### 没有硬件时会发生什么

仿真不是「降级模式」，而是**套在核心外面的壳**：`sim/harness.py` 给 `main()` 塞一个渲染器
和一个记录器，核心代码一行不改。所以开发机上的行为与实机的差异**只在这两个口上**。

反过来也要小心：`sim/arena.py` 把管道渲染成**平面折线**，它不产生管顶高光带，也不产生两侧
阴影 —— 而那两条是 [`hardware.md`](.dsh/agents/hardware.md) 列的头号失败模式。
**在仿真里跑通，不代表真实照片上不会锁到高光带上。**

### 三层验证阶梯

1. **单元测试**（`tests/test_logic.py`）—— 四条硬终止、上报去重、打舵符号。不依赖硬件也不依赖动力学
2. **仿真闭环**（`python -m sim.run_sim`）—— 整链路口径，但受占位动力学所限
3. **实机**（`python -m bionic_fish`）—— **未验证**：真实串口、飞控、GPIO、相机四段全是空白

## 六、动手前的约定

1. **git 分支纪律**：开发在 `dsh` 分支，`main` 保持现状；**合并到 `main` 需明确确认**。提交前把分支检查**当闸门**用，而不是打印一行就继续：

   ```sh
   [ "$(git branch --show-current)" = dsh ] || { echo "不在 dsh，中止"; exit 1; }
   ```

   工作区与另一个终端共享，HEAD 会被切走。「打印一行再继续」不算检查——2026-09-26 就这么把一次提交落到过 `main` 上，见 [`.dsh/logs/2026-09-26-branch-gate.md`](.dsh/logs/2026-09-26-branch-gate.md)。
2. **阈值一律进 `params.py`**：算法模块里不许有魔数，物理量阈值必须能追溯到标定（[不变量 7](.dsh/agents/invariants.md)）。
3. **`valid=false` 不等于 0**：绝不用 0 冒充「没看到」（[不变量 3](.dsh/agents/invariants.md)）。
4. **改完回写文档**：先 `.dsh/agents/` → 再 `.dsh/logs/` → 再日志索引。
5. **做完的 backlog 条目直接删掉**，不留痕（历史在 `.dsh/logs/`）。
6. **本机覆盖放 `AGENTS.local.md`**，它应该被 gitignore——那是给智能体的本机指令，不是项目事实。

## 七、现在到哪了

**能跑**：视觉、控制、状态机、上报决策、平台接口都已实现并有测试；合成场地上 0 与 ±30mm 三种起始条件**都能跑完全程、8/8 上报、约 25.4 秒**。

**卡着**：全部按「缺什么 / 找谁 / 为什么卡」记在 [`backlog.md`](backlog.md)。最卡的四件——

1. 车体上有没有可用的**航向 / 姿态源**（决定弯角是按角度转还是退化为限时双向搜索）
2. **实测动力学与平台接口**（决定占位数字能不能换成真值）
3. **误识别点的判别特征**（决定检测项 40 分的净值；默认配置实测 8 次上报只有 5 次命中真点）
4. **落盘与可视化调试界面没有实现**（没有它，前面三件在现场都说不清）

**`params.py` 里 63 个字段标了 `【待验证·实机】`**，列出来：

```sh
grep -n "【待验证·实机】" src/bionic_fish/params.py
```

**别做的事**：不要对着 `sim/plant.py` 的占位动力学调参。那不是在调系统，是在拟合虚构。
